SOURCES to ingest (all from list_sources seed table):

- BIS Entity List
- BIS Denied Persons List
- BIS Unverified List

INGESTION LOGIC — implement exactly in this order for each source:
1. Fetch the source file over HTTPS
2. SHA-256 hash the full payload
3. Compare hash against the latest list_versions row for this source
4. If hash unchanged: record the check with timestamp, exit — no further processing
5. If hash changed:
   a. Parse the source file per its format
   b. Normalise all entries into sanctions_entries, sanctions_entry_names, 
      sanctions_entry_identifiers — identical shape regardless of source
   c. Diff against current active entries: count added, removed, changed
   d. In ONE transaction:
      - Insert new list_versions row with added/removed/changed counts
      - Supersede the prior list_versions row (set status to SUPERSEDED)
      - Write all normalised entries
   e. Trigger re-screening cascade: flag open and recently-approved 
      compliance_cases involving affected parties for re-screening

FAILURE HANDLING — critical:
- On fetch failure: keep prior list_versions row ACTIVE, record failure, 
  set freshness indicator to STALE. Never discard good data.
- On parse failure: same as fetch failure — prior version stays ACTIVE.
- On partial failure: transaction rolls back, prior version stays ACTIVE.
