FIVE-STAGE PIPELINE — implement in exact order, no deviations:

STAGE 1 — Normalise
Implement the SAME rules as jobs/shared/normalise.js from Slice 2 in Python.
Rules must be identical — same suffix list, same honorific list, same particle rules.
Write as services/matching/normalise.py — a shared module used by stages 2 and 3.
- Lowercase
- Strip diacritics and accents (unicodedata.normalize)
- Remove legal suffixes: LLC, L.L.C., FZE, Ltd, Co., Inc., Corp., GmbH, S.A., B.V.
  and all common variants
- Remove honorifics: Sheikh, Dr., Mr., Mrs., H.E., Prof. and common variants
- Handle Arabic particles: Al-, El-, Ul-, Abd al-, Abu, Ibn, Bint
- Preserve original alongside normalised

STAGE 2 — Generate variants
Use the Arabic transliteration table from docs/05-technical-architecture.md section 7.3.
This is a DETERMINISTIC substitution table — not probabilistic, not ML-based.
Every known character combination maps to every known Latin equivalent.
Generate all variants for the input name and all its transliterations.
Write as services/matching/variants.py

STAGE 3 — Retrieve candidates
Query PostgreSQL sanctions_entries using pg_trgm trigram similarity.
Use similarity() function with a floor threshold (configurable, default 0.3).
This retrieves the candidate set — it does not produce the final score.
Never return more than 50 candidates to stage 4.

STAGE 4 — Score with rapidfuzz
For each candidate, score against ALL generated variants using:
- token_set_ratio
- token_sort_ratio
- WRatio (replaces JaroWinkler for better Arabic handling)
Take the MAXIMUM score across all variants and all algorithms.
Record which variant and which algorithm produced the maximum.

STAGE 5 — Return
Return all candidates above the minimum score floor (configurable, default 0.0).
Sort by score descending.
Include triggering_variant and triggering_algorithm on every result — 
these are compliance records, not optional fields.

CRITICAL RULES:
- Zero model calls anywhere in this service. It is deterministic by design.
- No model import, no Anthropic API call, no LLM of any kind.
- The triggering variant must be recorded on every result — not just the score.
- Normalisation rules must be identical to jobs/shared/normalise.js
